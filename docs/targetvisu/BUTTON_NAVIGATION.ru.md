# TargetVisu 0.4.0 — переход между экранами кнопками

Обновление исходников Editor и Python-модуля TargetVisu Runtime.

## Что изменилось

- В окне Runtime удалён верхний выпадающий список экранов. Строка состояния RUN/OFFLINE остаётся.
- В Editor у элемента button: Action → «Перейти на экран» → «Целевой экран».
- Переход работает в Preview и в нативном окне Runtime. Начальный экран задаётся прежней настройкой startScreen.
- Цель хранится как id экрана: переименование не ломает переход. Удаление экрана, на который ссылаются кнопки других экранов, заблокировано: сначала измените их цели.
- Навигация учитывает Visible/Enabled, не выдаёт разрешений записи переменных ПЛК. При переходе освобождаются удерживаемые кнопки текущего клиента.
- В Runtime действие, как и остальные кнопки, доступно при RUN и актуальных данных. При OFFLINE переход блокируется.
- Список экранов в Editor остаётся инструментом редактирования.
- Для возврата создайте на втором экране отдельную кнопку перехода на первый.

Старые проекты сохраняют прежние действия. Но после удаления списка Runtime проекту с несколькими экранами нужны кнопки навигации, иначе дополнительные экраны будут недоступны.

## Совместимость

Editor: Alexmoto/openplc-targetvisu, main 5e9fd5de754a201849091102c6b4d1933b7f8837, либо эта база с Editor Upload v0.2.1. Интеграция загрузки TargetVisu включена в обновление.
Runtime: установленный TargetVisu Autostart v0.3.0. Обновляются только файлы tools/targetvisu. C++-ядро, RETAIN, Modbus, конфигурация X11, службы и пользовательский проект не перезаписываются. Пересборка plc_main для этого обновления не нужна.

Это обновление не исправляет предыдущую ошибку сборки runtime_external_write_now: она относится к C++-ядру. Для работы с реальным проектом ядро и его TargetVisu-сокет уже должны работать.

Установщик проверяет все целевые файлы до записи, принимает LF/CRLF, создаёт резервную копию и откатывает запись при ошибке. Повторная установка безопасна. При «Modified source needs merge» файлы не меняются: нужна адаптация к вашим исходникам, не принудительная замена.

## Windows — Editor

Закройте Editor. Распакуйте архив. В каталоге с install_update.py:

```bat
py -3 install_update.py --editor "D:\Project_PLC\OpenPLC_Editor\editor-source" --check
py -3 install_update.py --editor "D:\Project_PLC\OpenPLC_Editor\editor-source"
cd /d D:\Project_PLC\OpenPLC_Editor\editor-source
npm run package
```

Нужны Python 3.10+ и уже настроенные зависимости сборки Editor. Установите/запустите новую сборку из release/build. Для привычного запуска из исходников можно использовать npm run dev вместо npm run package.

Откройте проект, создайте второй экран. На первом добавьте button, задайте текст, выберите Action → «Перейти на экран» и целевой экран. На втором создайте кнопку обратного перехода. Проверьте Preview, сохраните проект, скомпилируйте и загрузите его в Runtime.

## Banana Pi — Runtime

Скопируйте и распакуйте этот же архив на плате. В каталоге с install_update.py:

```sh
python3 install_update.py --runtime /root/openplc-runtime --check
python3 install_update.py --runtime /root/openplc-runtime
```

После установки перезапустите графический сеанс, чтобы автозапуск загрузил обновлённые Python-модули. Для вашей конфигурации LightDM выполните по SSH:

```sh
systemctl restart lightdm
```

Это закрывает текущие графические приложения. Уже настроенный автозапуск TargetVisu поднимет окно снова, когда проект будет RUN и его файлы будут корректны. Сам OpenPLC Runtime этой командой не перезапускается.

После загрузки проекта проверка:

```sh
cd /root/openplc-runtime/tools
python3 -m targetvisu check --project /root/openplc-runtime/core/generated
```

## Пример

examples/navigation.targetvisu.json содержит два экрана с кнопками перехода туда/обратно; examples/navigation.debug-map.json — соответствующий демонстрационный debug-map.

Его можно импортировать в Editor и проверить переходы в Preview без переменных ПЛК. Импорт заменяет текущие экраны после подтверждения — используйте тестовый проект. Пример не заменяет загруженный в Runtime проект автоматически.

## Резервная копия и откат

Путь targetvisu-navigation-backup-... печатается после установки. Для отката закройте Editor или графический сеанс, восстановите файлы из этой копии с сохранением относительных путей. Файлы, которых до установки не было, перечислены в created-files.json — удалите только их. Затем пересоберите Editor или перезапустите графический сеанс.

## Проверки

- Editor: 173 теста в 9 наборах — модель, Designer, сохранение, компиляция, упаковка, адаптер и pipeline.
- TypeScript: tsc --noEmit — успешно.
- Runtime: 33 теста прошли, 1 пропущен из-за ограничения AF_UNIX тестовой среды; потоковый протокол дополнительно проверяется через loopback TCP.
- Установщик: проверка, установка, повторный запуск, CRLF в Editor, отказ при изменённых файлах и сохранность C++-файла проверены на временных копиях.
- Нативное GTK/X11-окно и Windows EXE здесь не запускались: в среде нет GTK/X-сервера. Проверка на Banana Pi нужна после установки.

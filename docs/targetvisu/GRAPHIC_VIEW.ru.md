# TargetVisu 0.5.0 — Graphic View

Базовый примитив отображения изображений в Editor и нативном X11 Runtime.

## Использование

1. Обновите Runtime и Editor.
2. В TargetVisu нажмите **+ Graphic View**.
3. В свойствах выберите **Изображение PNG / JPEG** и загрузите файл.
4. Задайте положение, размеры и масштабирование: **Вписать с сохранением пропорций**, **Заполнить с обрезкой** или **Растянуть**.
5. При необходимости задайте **Visible when TRUE** — BOOL-переменную видимости.
6. Проверьте Preview, сохраните проект, скомпилируйте и загрузите его на плату.

Прозрачность PNG сохраняется. Изображения встроены в проект: отдельное копирование файлов на плату не требуется. JPEG преобразуется в PNG. Импорт принимает исходный файл до 8 МиБ, уменьшает его до 1024 пикселей по большей стороне и проверяет результат: до 1 МиБ PNG. Общий лимит документа TargetVisu — 4 МиБ, включая base64 изображений. При превышении компиляция выдаёт ошибку: уменьшите количество/размер картинок.

Graphic View в этой версии — статическое изображение. Смена изображений по значению тега (графический список), SVG, GIF-анимация и действия нажатия изображения пока не реализованы. Для управления используйте button. Как и другие декоративные примитивы, изображение выше кнопки в порядке слоёв перехватывает попадание указателя: размещайте кнопки поверх изображения.

## Runtime на Banana Pi

В вашей отдельной копии репозитория:

```sh
cd /root/openplc-runtime-github
git pull --ff-only origin main
cd updates/targetvisu-v0.5.0
python3 install_update.py --runtime /root/openplc-runtime --check
python3 install_update.py --runtime /root/openplc-runtime
```

После успешной установки перезапустите графический сеанс:

```sh
systemctl restart lightdm
```

LightDM закроет текущие графические приложения. Нативное C++-ядро/RETAIN не изменяются, пересборка plc_main не нужна. Python использует существующий Cairo из GTK-окружения; дополнительных пакетов на штатном TargetVisu не требуется. Скрытые курсор и строка RUN, а также навигация кнопками сохраняются: viewer.py этим обновлением не меняется.

## Editor на Windows

Если используете git-копию Editor, получите обновления в ней через `git pull --ff-only origin main`, затем пересоберите Editor командой `npm run package`.

Для исходников без git скачайте этот каталог обновления вместе с подкаталогами и выполните из него:

```bat
py -3 install_update.py --editor "D:\Project_PLC\OpenPLC_Editor\editor-source" --check
py -3 install_update.py --editor "D:\Project_PLC\OpenPLC_Editor\editor-source"
cd /d D:\Project_PLC\OpenPLC_Editor\editor-source
npm run package
```

Нужны ранее настроенные зависимости Editor и поддерживаемая Node.js 22/23. Установите новую сборку Editor, затем загрузите проект. Старый Runtime не понимает Graphic View, поэтому обновите его перед загрузкой проекта с изображениями.

## Совместимость и резервная копия

Пакет рассчитан на исходники Editor с Button Navigation v0.4.0 и Runtime TargetVisu v0.4.0. Установщик проверяет файлы до записи, сохраняет резервную копию, принимает LF/CRLF и допускает повторный запуск. При несовпадении пользовательских изменений остановится без записи; нужна адаптация исходников, а не принудительное перезаписывание.

Для отката восстановите файлы из напечатанного каталога резервной копии. Новые файлы перечислены в created-files.json. Проект с Graphic View не следует запускать на старой версии Runtime.

## Формат

Новый тип элемента: `kind: "graphic"`. Свойство `graphic` содержит `data` (встроенный PNG data URI) и `fit` (`contain`, `cover`, `stretch`). Остальные обязательные поля элемента сохраняются; `action.kind` должен быть `none`. Старые проекты без поля `graphic` поддерживаются.

В Runtime декодированные изображения кэшируются (до 4 изображений, каждое не более 1024×1024). Внешние URL, пути к файлам и SVG не принимаются. Повреждённый PNG, который нельзя декодировать, отображается серым заполнителем, ошибка записывается в журнал процесса.

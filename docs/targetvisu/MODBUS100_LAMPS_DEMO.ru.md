# Demo: 100 индикаторов по Modbus TCP на Banana Pi

Нативный проект OpenPLC Editor v4 хранится в каталоге
[`examples/Modbus100Lamps`](../../examples/Modbus100Lamps).
Это самостоятельный проект: не копируйте его `project.json`
поверх действующего проекта PLC.

## Конфигурация

- Главный экран **Main**, размер **1024×600**, 100 ламп (10 колонок × 10 строк).
- 12-цветный `Indicator style = lamp12`. 0 = скрыть, 1–12 = палитра ламп.
- PLC → Modbus Master → Modbus TCP: **192.168.1.138:502**, Unit ID **1**.
- Function Code **03 (Read Holding Registers)**, **0-based offset 0**, **length 25**,
  единый блок чтения, период **250 мс**, timeout **1000 мс**.
  **25 ioPoints не означают 25 Modbus-запросов**.
- Прочитанные WORD копируются из Modbus в `%MW0..%MW24`,
  переменные `MB_W00..MB_W24`.
- Группа содержит **25 ioPoints**, по одному для `%MW0..%MW24`.
  Это важно: компилятор проверяет наличие каждого канала, а не только
  `length: 25`. В ранней версии примера был всего один `ioPoint`,
  поэтому `%MW1..%MW24` оставались без источника.
- ST-программа `pous/programs/main.st` разлагает каждый 16-битный WORD
  в четыре 4-битных состояния; результат `Lamp001..Lamp100`.
- На экране индикаторы используют `bindings.value = Lamp001..Lamp100`
  (привязки к глобальным переменным, данные в проекте доступны без записей PLC).
- При ошибках связи установлено `errorHandling: set-to-zero`, чтобы
  очистить текущие лампы вместо сохранения устаревших цветов.

## Битовый порядок

**Младшая тетрада первая**:

| Регистр (с нуля) | Индикаторы | Биты слова |
|--:|--|--|
| 0 | 1, 2, 3, 4 | [3:0], [7:4], [11:8], [15:12] |
| 1 | 5, 6, 7, 8 | [3:0], [7:4], [11:8], [15:12] |
| … | … | … |
| 24 | 97, 98, 99, 100 | [3:0], [7:4], [11:8], [15:12] |

Пример: `%MW0 = 16#4321` даёт лампы 1/2/3/4 с состояниями 1/2/3/4.
Значение `16#0000` выключает все четыре лампы.
Значения тетрад `13–15` тоже дают невидимый индикатор.
Фактический первый запрос использует `offset: 0` (не 1 и не 40001).

## Запуск

1. Используйте **Editor + Runtime из ветки `feature/indicator-lamp12`**,
   либо новее с поддержкой 12-цветных ламп.
2. Загрузите папку `examples/Modbus100Lamps` как новый локальный проект
   (через **Open Project**, укажите сам каталог или его `project.json`).
3. Откройте Remote Devices → `LampSource`, проверьте IP, порт, Unit ID.
4. Выберите устройство с OpenPLC Runtime v4. Скомпилируйте PLC-проект;
   для проверки из терминала можно использовать
   `openplc-cli compile <path-to-project> --target "OpenPLC Runtime v4"`.
5. Загрузите скомпилированный проект и запустите его на Banana Pi.
6. Меняя Holding Registers 0..24 на сервере `192.168.1.138`, наблюдайте
   обновление всех 100 ламп.

При тестировании нового ПО на работающем оборудовании убедитесь, что
оборудование находится в безопасном состоянии. Это **только read-only HMI**:
Modbus Master читает, но не пишет в удалённый сервер.

## Ограничения

Компиляция в локальном Windows Editor и доступность Modbus-сервера по IP
не могут быть подтверждены из GitHub CI. Автоматический тест в
`src/backend/shared/compile/steps/__tests__/generate-targetvisu.test.ts`
проверяет схему проекта, все 100 привязок, конфигурацию одного 25-словного запроса
и синтетическую выгрузку TargetVisu. Реальная загрузка и IEC-компиляция
проверяются отдельно на целевом Runtime.

Если сервер использует обратный порядок тетрад (сначала [15:12]),
замените последовательность сдвигов `0,4,8,12` на `12,8,4,0`
в файле `pous/programs/main.st`.
